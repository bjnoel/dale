# 2026-08-10 — The daily digest gets a memory

**Decision:** [DEC-272](../decisions/decision-log.md)

## What happened

Benedict asked whether Dale's daily digests were readable anywhere online, or whether
they only existed in his inbox. They only existed in his inbox.

The digest is the report Dale emails every morning at 6am AWST: what's waiting on
Benedict, which tickets were graded against the metric they promised, traffic, and
what shipped in the last 24 hours. It was built in memory, handed to the email
provider, and dropped. Nothing kept a copy.

That matters more than it sounds, because the digest opens with "Waiting on you" — on
2026-08-09 that was 26 tickets, 9 of them more than 30 days old. The most re-readable
part of the report was the hardest part to get back to.

## What shipped

`/admin/digest` on treestock, behind the same Cloudflare Access gate as the rest of the
admin view. It shows the newest digest by default, with older ones reachable through a
pager and a month-by-month archive list.

The archive did not start empty. The email provider keeps the HTML it sent and hands it
back on request, and what it hands back is exactly what Dale generated, so 29 days of
history were recovered on day one: 2026-07-12 through 2026-08-09, no gaps. Anything
older has already aged out of the provider's retention window and is not recoverable.

## Worth noting

Three things were checked rather than assumed, and two of them would have been wrong.

**The access gate.** The question was whether the rule protecting `/admin` also covers
`/admin/digest`. The management API reported no access rules at all, which turned out to
be a permissions artefact rather than the truth. Probing the live site settled it: every
path under `/admin`, including ones that do not exist, redirects to the login. The server
was then checked separately and refuses any `/admin` request without a valid token, so
the two protections hold independently.

**The deploy restart.** The deploy script only restarts the web service when a checksum
of its modules changes, and that checksum listed the files by name. A new file would not
have been in it, so a future fix to the archive would have sat on disk while the old code
kept serving. This has bitten this project before. It is in the checksum now.

**The web server config.** The live config had drifted from the tracked copy: it carries
a block for an unrelated service that the repo does not know about. Overwriting it with
the tracked version would have quietly deleted a working service. The live file was
patched in place and validated instead.

## And then it got split up

Benedict's follow-up, once the digest archive was in: the main admin page had become one
long wall of text. It was rendering about 91KB in a single document — business state,
subscriber tables, a 27-nursery relationship register with expandable histories, a
two-week scraper health grid, and an unclassified-products report, all stacked.

It's four tabs now. The landing page is business state alone, about 11KB, which is the
only page that asks anything of the reader. Subscribers and nurseries each get their own
tab, and the digest archive joins the same navigation. Scraper health went with the
nurseries rather than the business page, because it answers the same question the
relationship register does, just from the scraper's side.

One thing broke in the move and is worth naming. The nursery section carried a sentence
saying open actions were "also listed at the top of this page". That was true when
everything was one document and false the moment business state became its own page. No
test caught it, because no test asserted on a sentence that had been correct for two
months — it was caught by rendering the page and reading it. It's a link now, with a test
pinning it. Cross-page references have to be links, not directions.

## Cost

$0. About 6KB a day of storage.
