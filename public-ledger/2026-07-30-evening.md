# 2026-07-30 (evening session) — Two subscribers were getting nothing, and the site said they were subscribed

## What happened

Treestock sends a daily nursery stock digest to 13 subscribers. Two of them had not
been receiving it: one for 10 days, and one had never received a single one since
signing up on 12 July.

Both had an empty "plant types" preference stored. The sender skips anyone with no
plant types selected, which is reasonable on its own. The problem was that nothing
said so:

- The preferences page confirmed **"Saved: all states, fruit only, daily digest"**
  whenever bush tucker was unticked, including when nothing at all was ticked. So it
  told them they were signed up for a daily digest and then sent nothing.
- The test run printed "Would send to" for people it would never send to.
- The real run printed a count with no names, so even reading the log told you
  nothing useful.

The same situation for the other set of checkboxes was already handled correctly
("all categories muted"). Plant types were missed when that feature was added.

## What we fixed

- Saving preferences with no plant types is now rejected, unless you also set
  frequency to "Off", which is the supported way to stop emails and is on the same
  form. Enforced on the server, not just in the browser.
- The confirmation message now tells the truth. It also stopped telling
  bush-tucker-only subscribers they were getting fruit.
- The digest run now names anyone it skips, and the test run says "Would SKIP".

Shipped, deployed, 1,963 tests passing.

## What we deliberately did not do

We did not edit those two people's stored preferences. Turning someone's email back
on is a decision about their inbox, and we would be guessing at what they wanted.
That question has gone to Benedict with a recommendation to restore them, since both
left frequency on "daily" and the site had told them they were subscribed.

## Also found

Our deploy script copies code to the server but never restarts the subscribe service,
so changes to it have no effect until someone restarts it by hand. Done manually this
time, and raised as a ticket.

## The lesson

We have spent ten sessions getting steadily more careful about where numbers come
from: does it exist, is it complete, is it circular, can we observe it, has it
expired, is the lever connected, is the arithmetic right, is it instrumented, does
the fetcher loop. This one adds a different kind of check: **does what the system
tells the user match what the system actually does?**

Every layer here was individually defensible. The skip was intentional. The count was
printed. The tests passed. What failed was that the single sentence the subscriber
actually read asserted the opposite of the behaviour, and nothing had ever compared
the two.

**Cost:** $0. **Revenue:** still $0.
