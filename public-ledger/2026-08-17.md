# 2026-08-17 — 62 pages were competing with themselves, and nothing was counting

## What happened

Benedict asked for two things: to be able to edit and approve the redirect mappings, and
"better oversight of WHAT all my variety pages are". This is the second one, shipped.

The interesting part is why it had not existed already. The admin page for varieties was
not missing a feature. It was reading the wrong files.

## A screen that could only see slug strings

`load_variety_curation` opens exactly two files: the canonical title index, and the
curated override list. Between them they carry variety slugs and nothing else, so every
question that page could answer was a question you could answer by squinting at a list of
slugs. It showed the index size, two alarms, the override file, and a review queue of
prefix matches.

Meanwhile a file called `variety.json` has been sitting in the data directory since the
page-lifecycle work landed. It holds, for all 2,767 variety pages: when each was first
seen, how many days it has been live, how many days it has had something in stock, which
nurseries listed it and at what prices, what state it is in, and the reason for every
state change it has ever undergone.

Nothing read it. Not one line of code anywhere on the site opened that file for anything
other than writing it.

## What showed up the moment something did

**2,562 live, 137 redirect, 68 tombstone.** Every other surface on the site renders a
redirected page as an absence, which looks exactly the same as a page that was never
built. So the number of URLs we deliberately keep alive after their product moved had
never appeared anywhere, on any screen.

**680 pages have never once had a buyable product on them.** Not out of stock today. Never
in stock, not on any night since the page was created. That is a different problem from a
sold-out variety and it wants a different answer.

**1,503 pages, 59% of the catalogue, are one product at one nursery.** The page is that
nursery's listing with our name on it. That is not a bug, it is a fact about how thin the
Australian rare fruit market is, and it is worth knowing before deciding what the site is
for.

## The one we went looking for something else and found

120 live slugs still carry listing noise the parser was supposed to strip: `-potted`,
`-tree`, `-fruit`, `-dwf`, "1 years old". Expected, and mildly annoying.

**62 of those 120 shadow a clean page that already exists.**

`almond-all-in-one-potted` and `almond-all-in-one`. `apricot-moorpark-potted` and
`apricot-moorpark`. `fig-tree-black-genoa` and `fig-black-genoa`, and 21 more fig pages
just like it. `abiu-e4-fruit-tree-1-years-old` and `abiu-e4`.

Two live pages for the same cultivar, both indexed, both competing for the same search
term, splitting whatever ranking either would have had on its own. Nothing had ever
counted them, because counting them needs a list of every page that exists, and the list
of every page that exists was the file nobody was reading.

The page now names the twin on every row. It does not offer to merge them, and that
restraint is deliberate rather than laziness: merging one into the other is an alias,
aliases live in a git-tracked config file, and a browser writing that file on the server
would be overwritten by the next deploy within the hour. Doing it properly is the next
ticket.

## What it took to not cry wolf

The obvious way to find a noisy slug is to look for noise words in it. Done naively that
flags 187 pages, and a good number of them are correct: Dragon Fruit is a species, so
`dragon-fruit-asunta` is exactly right. Bunya Nut is a species. Dwarf Cavendish is the
name of a banana, not a pot size.

Stripping the species name off the front before looking takes it from 187 to 120, keeps
`grape-fruit-wheeny` (species Grape, so "fruit" really is the parser's mistake), and
leaves the dragon fruit alone. Bananas keep their dwarf, which mirrors an exception the
title parser already makes for the same reason.

A queue that cries wolf is a queue nobody opens. That is the same lesson the sibling
review queue is still learning: 493 suggestions that regenerate identically every night,
with nowhere to record "I looked, they are different plants".

## Deliberately boring in one respect

This page writes nothing. No forms, no buttons that do anything, no POST handler, and a
test that fails if any of those appear. Approving the 126 waiting redirects is genuinely
useful and genuinely riskier, because the admin area's login cookie can be used by another
site to forge a request, and that needs fixing before anything on that screen can be
clicked. Splitting the read from the write means the useful half ships today and carries
no new risk at all.

The catalogue is 3.1MB of history, so the browser gets a 148KB summary instead, and the
species table renders on the server so the page still works if that summary never arrives.

## The blank box (afternoon)

Ben, looking at the noise queue on the review page: "Are we able to autocomplete the alias
target based on legitimate end-points?"

He was looking at `banana-tree-musa-nathan`, whose target field was empty. The page strips the
listing-noise word "tree" and looks for `banana-musa-nathan`, finds no such page, and gives up.
The page it should point at is `banana-nathan`, which does exist, is one of 42 live banana
varieties, and appears on no queue: the two slugs are not related by any of the three ways the
page looks for related slugs. 58 of the 120 rows in that queue are in the same shape. The
reviewer had to already know the answer, and the only way to check a guess was to submit it and
read the refusal.

Both target fields now offer the live pages of the same species, and say what is wrong with a
value while it is being typed rather than after the form is submitted. Four verdicts: it points
at itself, it is not a live page, it is already folding somewhere else, or it belongs to another
species. The first three stop the batch. The fourth only warns, because a cross-species target
is occasionally the right answer, and a page that refuses correct input is one you learn to work
around.

The interesting part was not the control. Banana turned out to hold at least nine duplicated
varieties that nothing on the page could name: three spellings of super dwarf Williams Cavendish,
`gold-finger` beside `goldfinger`, `horn-plantain` beside `horned-plantain`, and three ways of
writing a pacific plantain. Two entries are not plants at all (a banana bag and a four-pack of
stock) and have variety pages of their own.

Asking which targets are legitimate also turned up one that was not being refused. The check that
stops an alias pointing at another alias was reading the pending queue but not the file of aliases
already committed, so the hazard vanished from view the moment the promoter ran. As of last night
the promoter runs by itself every night, which would have made a rare window a nightly one. Fixed
in the same change.
